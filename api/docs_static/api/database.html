数据库与数据口径

空间监测插件以 PostgreSQL + PostGIS 保存目录、轨道根数、传播轨迹、风险结果及外部增强数据。Orbit Copilot 调用的是同一套 REST API；查询结果与监测系统页面使用同一数据库和统一视图，不维护一份独立副本。

当前库实时概况
主目录 — 个目标；GP/TLE — 条； 传播轨迹段 — 条；去重统一目录 — 个目标。

数据时效、口径与限制

  • 时间口径：接口时间统一使用 UTC；GP/TLE 的 epoch 是轨道根数历元，不等于数据下载时间。
  • 高度口径：目录检索的平均高度由近地点与远地点高度计算；太阳同步标签由高度与倾角关系进行工程判定。
  • 统一口径：同一 NORAD 编号存在多个来源时，由 datasource_priority 中数值更小的来源优先，增强字段按可用性补充。
  • 空值：质量、尺寸、用途和运营方并非所有目标都公开；空值表示当前数据源未提供，Orbit Copilot 导出时会保持为空。
  • 预报限制：TLE/SGP4 适合近期工程预报，不等同于高精度定轨产品；碰撞与再入结果应结合数据历元和模型假设使用。
  • 敏感信息：数据库账号、密码、Space-Track 凭据和服务令牌不会在本文档或 API 响应中展示。

与 Orbit Copilot 的关系

启用“空间碎片监测”插件后，Orbit Copilot 会从当前用户配置的 API 地址同步全部非敏感 OpenAPI 操作。类似“查一下 600–800 km 高度、太阳同步轨道的卫星列表，请导出一个 xlsx”这类请求，会先调用目录检索接口取得真实结果，再在本机生成 Excel 文件并由用户选择保存位置。

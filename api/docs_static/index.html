空间碎片监测与发射碰撞风险评估系统

本系统是一套面向航天发射任务规划人员和空间碎片研究人员的全链路空间态势感知平台。从数据采集、轨道预报，到碰撞风险评估和发射窗口优化，提供端到端的决策支持。

系统整合了 Space-Track、UCS、ESA DISCOS、GCAT、UNOOSA 五大权威数据源，统一去重后形成 60,000+ 在轨目标的综合目录，并独立接入 Asterank 小行星 / 近地天体（NEO）专题库 与 NASA TechPort 航天技术项目组合（约 20,000 项目）；同时提供 10 个交互式功能页面（含规避策略 + 太空事件管理）和 19 个 REST API 接口（含数据源管理与太空事件管理）。

核心功能一览

系统概览面板

一目了然掌握全库在轨目标总量、各类型分布、数据摄入状态和发射历史趋势。

可视化探索

正射球面和 3D 地球上实时观看碎片运动，高度分层下钻，区域碎片搜索，轨道预报。

目标目录

多源融合的统一目标数据库，支持按数据源、国家、类型、RCS 等维度筛选与检索。

轨迹仿真

CZ-5B / Falcon 9 / Ariane 6 火箭 6-DOF 轨迹仿真，3D 可视化飞行全过程。

LCOLA 飞越筛选

扫描 ±N 分钟发射窗口，找出禁发时段，推荐最安全发射时刻。

碰撞风险评估

对发射全过程逐阶段计算碰撞概率 (Pc)，四级风险预警 + 规避建议。

规避策略生成器

对高风险合取事件给出三类机动方案：B 平面解析脉冲 / 持续小推力 SCP / 上升段时空走廊 + MPC，输出 ΔV、推进剂、修正轨迹。

太空事件管理

融合 ESA DISCOS / Space-Track CDM 与本地手填事件，NASA SBM 解体模拟生成碎片云，CCSDS CDM/OPM/OEM/OCM/RDM 标准导入导出。

长期风险评估

基于泊松统计和 ORDEM/MASTER 通量模型，预测卫星寿命期内的累积碰撞风险。

AI 智能助手

用自然语言提问，AI 自动调用分析工具返回结构化分析结果。

部署最低硬件配置要求

本系统是一套自带数据库 + Web 前后端 + 后台任务的复合应用，建议按以下最低规格部署。 开发期实测在该规格下可流畅运行所有页面（含 6-DOF 仿真、LCOLA 飞越扫描和 STK 跨算法验证回归脚本）。

💻 推荐最低规格（开发 / 内部演示用）

部署
项目最低值说明
CPU 2 核（x86_64，支持 SSE4.2） 6-DOF / SBM / Foster Pc 主要靠 numpy / scipy 向量化运算；核心数越多越好，但 2 核已能跑完所有页面。
内存 10 GB 典型分配：PostgreSQL ~2 GB（含 shared_buffers）／ FastAPI ~1 GB ／ Streamlit ~2 GB ／ 缓存（LCOLA 扫描、SGP4 propagate）~3 GB ／ 系统预留 ~2 GB。
硬盘 80 GB（推荐 SSD） 典型占用：PostgreSQL 数据 ~25 GB（融合目录 + GP 历史）／ TechPort 索引 ~3 GB ／ venv + 依赖 ~6 GB ／ STK 可选 ~30 GB ／ 日志 + 中间产物预留 ~16 GB。
操作系统 Linux 或 Windows 均可 推荐 Ubuntu 22.04 LTS / Debian 12 / Windows 10+ / Windows Server 2019+。 所有核心算法纯 Python，跨平台一致；仅 STK 验证只能在 Windows 上启用。
Python 3.10 – 3.12 已在 3.11 上做主要回归。需要 venv；不建议混用系统 Python。
网络 出网带宽 ≥ 2 Mbps 用于数据源增量拉取（Space-Track / DISCOS / GCAT / TechPort）和可选的 Cloudflare 隧道； 完全离线部署也可（启动后内部回退到本地缓存）。

🚀 推荐生产规格（多用户 / 公网常驻）

扩容
项目推荐值说明
CPU4 核及以上并发 ≥ 5 个 Streamlit 会话时强烈建议 4 核，能让 LCOLA 后台扫描和前台交互不互相阻塞。
内存16 GB给 PostgreSQL 提升到 4–6 GB shared_buffers，并发查询和 GP 增量入库会更快。
硬盘160 GB SSD多用户场景下日志、CCSDS 文件、OEM 导出会显著增长，预留出空间。
STK 跨算法验证Windows + Ansys STK 12.1+仅在 Windows 上启用；Linux 部署会自动屏蔽相关按钮，其它功能不受影响。
